# 构面原始曲线的保留与交付

## 默认要求

建模不仅交付曲面，还要交付实际用来构面的原始输入曲线。除非用户明确要求删除，所有可保留的构面曲线都必须作为真正的可编辑曲线对象保存在最终 Rhino `.3dm` 中，归入名为 `lines` 的图层。不能只存在于 Python 内存、日志、截图或临时文件中。此要求贯穿试面、修改、清理与保存阶段。

可以在 `lines` 下按面块/角色/版本建子图层，例如 `lines::P01::rails`、`lines::P01::sections`、`lines::P01::boundaries`、`lines::P01::archive`。简洁项目可全部直接放入 `lines`。允许为展示隐藏图层，但不能在清理时删除；交付告知如何显示。沿用已有合适图层，不更名或移动与本任务无关的用户对象。

## 按真实输入保留

| 构造 | 应保留的实际输入 |
|---|---|
| Sweep1 | 一条轨道及全部参与构造的截面 |
| Sweep2 | 两条轨道及一条或多条参与构造的截面；不是一条轨道加两条截面 |
| Loft | 全部输入截面，记录顺序、方向与闭合接缝位置 |
| EdgeSrf / NetworkSrf | 实际边界曲线 / 两族网络曲线及对应关系 |
| Revolve / RailRevolve | 实际剖面、旋转轴起止定义，以及实际使用的轨道 |
| Extrude / 曲线驱动修剪、切割 | 输入轮廓，以及实际使用的路径或切割曲线；直线方向/距离另记参数 |
| Blend / Match / 由已有面边构造 | 保留父面和所选边的身份、参数范围与条件；有实际独立输入曲线则一起保存 |

没有曲线输入的直接控制网建面不必事后编造“原始线”；保留可编辑母面和控制网/生成参数。可提取辅助检验线，但标明 `diagnostic` 或 `derived`，不能冒充原始生成线。

真实面边的 G1/G2 条件依赖父面横向导数。单独 DupEdge 只保留边界位置，不能替代父面或证明可以仅靠曲线重建同等连续性。

## 执行步骤

1. 构面前为输入曲线分配稳定名称/ID，例如 `P01_rail_L_v01`、`P01_section_03_v01`。记录来源、角色、方向和顺序。
2. 脚本在内存中生成曲线时，将**实际传入构面调用的最终版本**持久化为文档曲线；记录添加返回的 GUID。输入已是文档对象时保留其身份，不无意义地重复复制。仅内存测试可以不落盘，但正式模型交付前必须完成此步骤。
3. 构面命令使用保留输入的选项；无此选项或不确定会否消耗/修改输入时，先保留副本。API 操作若需修改输入，使用副本，保存用于本次构面的实际最终曲线。
4. Rebuild/Fit/Fair、反向、改接缝等会影响施工时，保存对应版本及操作/参数；原始参考与最终构面输入分别标记。保留具有设计意义的试验和回退版本，不为每次显示操作制造重复对象。
5. 为输出面记录 `patch_id`、方法、输入曲线 GUID/名称/角色、顺序、参数与父面依赖。可用对象 UserText 和项目记录共同保存，字段方式不依赖特定 MCP 工具。
6. 清理只处理明确可丢弃的临时物，不能按“已用过”删除构面线，不能删除整个 `lines` 层。曲线被用户修改后，应更新映射或标记与现有面的版本差异。

## 验收与修改说明

保存前核查：`lines` 存在；本次实际构面线仍为有效文档曲线；GUID 与面块映射可解析；数量、顺序和角色完整；隐藏不等于删除。保存 `.3dm` 时包含这些图层和对象，不能仅选择成品面导出而遗漏。需要验收落盘持久性时，在独立文档/读取环境复核，不覆盖用户当前场景。

STEP/IGES/STL 等交换或制造文件按用途另行输出，不保证携带相同图层、曲线、映射或历史；可编辑的 `.3dm` 为配套交付。只交付交换格式时，明确说明编辑资料的存放方式。

**保留曲线不等于启用关联历史。** 仅当当前命令、运行方式和 Rhino 历史设置确实建立并验证了关联，才能承诺改线自动更新面。否则告诉用户：可显示 `lines`，修改相应轨道/截面，按记录重新执行构面及后续检查；已有修剪、Match 和细节可能需要重做。
