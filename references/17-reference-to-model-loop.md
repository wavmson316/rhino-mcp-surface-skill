# 图片到三维：逐步拟合、验收与提速

复杂参考建模前必读。目标是减少形体误差并保留修改能力，不是执行尽可能多的构面命令。

## 1. 把参考转换成可检查的事实

实际查看用户用于本次建模的图片，先分清遮挡、材质、反射、零件缝和真实折棱。用户禁止读扫描教材，不等于永久禁止查看建模参考；若本次参考确实不能查看，明确只能执行用户提供的几何描述，不能声称图片还原通过。

为每个视图记录文件、画幅、裁切、投影、镜头/姿态假设；建立主轴。选择足以辨认物品的锚点：前后端、顶高点、最宽处、肩线转折、凹区最深位置、孔口中心/开口宽度等，按实际可见性取舍。填写 [参考记录](../templates/reference-fit.json)。像素坐标只约束投影；不能把单张透视的像素直接换成三维坐标。被遮挡点不编成实测值。

记录每个关键特征的目标位置/比例、可靠度、允许偏差和当前残差。尺寸未知可令 L=1；厚度、装配间隙和背面作为独立假设。照片看不见的法截面不能冒充测量。圆润程度、肩线硬度、负空间和深凹常比全局包围盒更有辨识力。

## 2. 相机与粗体量先通过

先用解析体或少量可调控制网构成粗体量。集中调总长宽高、最大宽/高点位置、前后收束、主要负空间，暂不做倒角、纹理、密孔和螺钉。不是所有物体都应由一张面表达，但初始无需完成全部细分。

先匹配投影类型、朝向、焦距/相机距离和裁切，再锁定比较相机。必要时用两三个合理深度假设比较；选择有证据的方案。相机需要重新校准时建立新比较版本，旧版/新版在同一新相机下重算，不能移动相机来掩盖造型误差。

低分辨率预览已能显示重大差异时，不先做精细曲面。出口至少要回答：轴与朝向是否正确、长宽高比例是否合理、主高点/最大宽位置是否接近、主要孔与凹区是否在正确区域。阈值由参考可靠度/任务决定；不能虚构固定 IoU 即合格。

## 3. 主面按体量职责构建

为主高光、侧腹、凹底、过渡和收口分别确定职责。面块由需要独立控制的形体和邻接导数决定，不按图像像素或每条零件缝切碎。优先让少量稳定母面跨越最终修剪域。见 [曲面优先决策](15-surface-led-construction.md)。

先做最能决定身份的主面或局部试面；检查实际曲面，而不是仅检查输入线。若选择 Network，必须有两族独立形状依据且交点一致；没有依据就不要生成密网。Network 拟合的是曲线约束，网格之间也需要独立检查，面数不等于网格格数。Loft、双轨或控制网均需说明约束是否被表达；“换命令”不等于解决形体推断错误。

实际比较前后侧轮廓、纵横和斜向截面；尤其检查生成截面之间、极值附近和特征消退处。只检查自己提供的输入线会形成自证。关键轮廓位置正确但体量仍显肉，先检查横向圆扁、肩部宽度、前后衰减，不默认再加截面。

## 4. 每轮只有一个可检验假设

```text
差异：参考肩部在更低位置，模型侧腹过圆。
假设：肩部过渡带太宽，而不是整体宽度不足。
只改：肩部位置与过渡宽度；保留总宽、顶部高点、相机。
重算：受影响面与下游过渡；检查肩部锚点、侧剪影、凹深及旧接缝。
保留：残差改善且关键旧约束未越预算的候选；否则回退。
```

先修最大的可解释误差，再修小细节。检查表同时保留局部关键特征和整体指标，不能用全局 IoU 提升掩盖小孔消失、凹深错误或破面。不同模型分别按自身质心/外半径归一化会掩盖尺寸与位置变化；相机、裁切、单位和配准变换应锁定。有必要做尺度无关比较时另列指标，不取代固定条件比较。

连续两轮同类调参无改善，检查相机/深度假设、未受控边界和布局，换一个有依据的方案；不要无限加线。这个停止规则用于防止盲目循环，不是几何定理。

## 5. 主形通过后再做细节与工程

依次处理局部过渡、端部、孔壁、装配分件；母面通过后再派生细小开孔/格栅。每个关键特征都有对象 ID、目标、实际值和验证状态。曲面质量、参考相似度、拓扑和工程分别验收。单图不唯一恢复背面或深度；补全应可调整并标明假设。

## 6. 提速的执行方式

- 接入时集中发现一次工具/API；仅在版本变更或调用失败时重新核验。先检查 `module.__file__`，源码变更才 reload；删除磁盘缓存不会刷新已加载模块。
- 优先原生 API 在内存中构造，`patch_with_lines` 默认 `register=False`。一批按依赖建少量相关母面，返回 ID、边界框、有效性、耗时和检查摘要；避免每条点/线一次 MCP 往返，也不一次塞入整机所有步骤。
- 一次参数更新只重算受影响面及其下游。通过后再显式 `publish_patch` 落文档，不把每个试件全部叠在场景里。保留原始生成线至 `lines`，记录版本。
- 低复杂度/低成本预览检查大形，局部加密检查疑点；每个有意义阶段取固定相机和必要局部截图。参考保真任务不能为了省 Token 完全取消视觉核对。
- 单元先验收再阵列；尽量延迟密孔、细网格、显示细化和昂贵布尔。失败或超时先查状态，不重放整个脚本。
- 分别记录构造、验证、截图、MCP 往返耗时，优化实际瓶颈。不声称减少曲线或改命令一定带来固定倍数提速。

## 7. 证据与边界

本流程尚未以用户失败参考完成端到端验证。基础 API 通过不能证明图片还原成功。最终报告列出参考条件、关键特征残差、面块方法、结构/接缝结果和未确定区域；若主形未通过，应交付带问题标记的阶段版本，不能堆细节后称成品。
