# 构面路线选择与曲线留存

> 本篇解决两个反复出现的实际问题：
> 1. AI 一遇到复杂物体就"画几条界面线 + Loft"，做出**内部体量失真**的曲面
> 2. 构面用的输入曲线没留在文件里，用户**无法二次修改**
>
> ⚠️ 本篇不是可选参考。**复杂物体开工前必读。**

---

## 1. ⛔ 为什么"画几条线 + Loft"是错的

### 1.1 Loft 不产生控制点，它只是"连接"控制点

Loft 在相邻截面之间做**插值**。截面少 → 插值区间大 → 曲面在区间内部
**没有任何约束**。你在截面上看到的一切都对了，但**两个截面之间那段完全是编的**。

```
3 条截面 Loft        5×5 网格 NetworkSrf
                                           
 ┃      ┃            ┃ ┃ ┃ ┃ ┃
 ┃      ┃     →      ┃ ┃ ┃ ┃ ┃
 ┃      ┃            ┃ ┃ ┃ ┃ ┃
 ┃      ┃            ┃ ┃ ┃ ┃ ┃
                    
 段内无约束          段内处处有约束
```

### 1.2 ⭐ 实测：同一壳体，两种做法

在 80×50×12 mm 的收缩壳体上实测（收缩率 25%）：

| 做法 | 输入曲线 | 内部体量可信度 |
|---|---|---|
| 3 条截面 + Loft | **3 条** | ⛔ 截面之间完全失真 |
| 5×5 网格 + NetworkSrf | **50 条** | ✅ 每格都有约束 |

⚠️ 关键结论：**曲面质量取决于输入曲线的数量与分布，不取决于用哪个命令。**

⛔ `Loft` 不是坏命令，`NetworkSrf` 也不是好命令 ——
**用 3 条线去 Loft 就是错的，用 50 条线去 Loft 反而没问题**（只是没必要）。

### 1.3 ⛔ Loft 的三种典型误用

| 误用 | 后果 |
|---|---|
| 用 Loft 做**四边面块** | 4 条闭合边不是"有序截面"，得到的是扭曲管状面 |
| 截面只画外轮廓，不画**内部结构线** | 内部无约束，体积凭空编造 |
| 靠**增加截面数量**救 Loft | 应该换网格线或 NetworkSrf，不是加截面 |

⚠️ 例外：`Loft` 真正合适的是**等截面族** —— 截面形状相似、位置递进、
无需内部控制（如渐变杆件、同截面梁）。⛔ **复杂自由曲面不属于这一类**。

## 2. ⭐ 构面路线的选择顺序

⛔ **不是"选一个命令"，是"先判断需要几个方向的约束"。**

```
问自己：这个面在【U】方向需要几个控制点？在【V】方向呢？
```

| 需要的约束 | 正确做法 | ⛔ 不要用 |
|---|---|---|
| U 方向多条、V 方向单条 | `Sweep1`（路径+截面）| Loft 硬凑 |
| U、V 都要多条（**最常见**）| `NetworkSrf`（网格线）| ⛔ **Loft** |
| 只有 4 条边界，内部自由 | `EdgeSrf` | Loft |
| 两母面之间的过渡带 | `BlendSrf` | Loft |
| 已有面要改形状 | `MatchSrf` | 重建 |
| 等截面（相似、递进）| `Loft` ✅ | — |
| 完全规则（旋转/平移）| `Revolve` / `ExtrudeCrv` | — |

### 2.1 ⭐ 网格线怎么布（NetworkSrf 的实操）

**关键原则：网格密度由曲面的曲率变化决定，不由"看起来够不够"决定。**

```
1. 先画【边界线】—— 曲面的四条边，它们是硬约束
2. 在每个方向上，从边线等分往内布
3. 在曲率变化大的区域加密，平坦区可疏
4. ⛔ 网格线不要超出边界太多（求交余量即可）
5. ⛔ 两族线必须【干净相交】——不相交会得到废面
```

**验证动作**：`NetworkSrf` 后立刻检查——
- 面数是否 ≈ (U线数−1) × (V线数−1)
- 有无多余碎片
- `CurvatureAnalysis` 的色谱是否均匀

### 2.2 ⭐ 什么时候 Loft 是对的

⛔ **不要一刀切禁止 Loft** —— 它在以下情形是正确的：

- 截面**形状相同、只沿一个方向平移/旋转**（渐变、阵列杆件）
- 放样家具的直线段（截面就是同一个轮廓平移）
- **加截面确实能表达形体** —— 也就是形体本来就由截面序列定义

⛔ **判断错��**：如果"再加两条截面"能让形体更准，那是网格线问题，不是截面问题。

## 3. ⭐⭐ 构面曲线必须留在文件里

### 3.1 为什么这是硬要求

构面用的输入曲线**就是用户未来的修改入口**。丢掉它们意味着：

- ⛔ 用户改不了形体 —— 只能整张面重做
- ⛔ 无法回答"这条边为什么在这里"
- ⛔ 无法局部调形 —— 曲面是烘死的
- ⛔ 交付物**不可编辑**，失去 NURBS 的意义

⚠️ 这是**交付要求**，不是"最佳实践"。

### 3.2 ⭐ 规则：所有构面输入曲线进 `Lines` 图层

```
每一张曲面在构造时，把它的【全部输入曲线】放入 Lines 图层。
```

| 构面方式 | 必须保留的曲线 |
|---|---|
| `Loft` | 全部截面曲线 |
| `Sweep1` | 路径 + 截面 |
| `Sweep2` | **2 条 rail + 全部截面** |
| `NetworkSrf` | 全部 U 向 + 全部 V 向线 |
| `EdgeSrf` | 全部边界线（3 或 4 条） |
| `BlendSrf` | 两侧的边线 |
| `Patch` | 全部输入曲线/采样点 |
| `MatchSrf` | 目标边与被匹配边 |

⚠️ `Sweep2` 只是**最容易被忽略**的那个 —— rail 两条 + 截面若干，
很多人只留了截面，结果无法改路径。

### 3.3 ⭐ 图层约定（可直接用）

```
文档
 ├── Lines        ← 所有构面输入曲线（构面记录的真相）
 ├── Surfaces     ← 曲面（可按面块分层）
 └── Guides       ← 可选：参考线、轴线、构造辅助
```

⚠️ 若文档已有分层约定，**保持一致**，但必须让"输入曲线"可被找到。

### 3.4 ⭐ 现成封装：`scripts/patch_with_lines.py`

比每次手写更省事，也更不容易漏：

```python
import sys; sys.path.insert(0, str(skill_root / 'scripts'))
import patch_with_lines as PWL

# NetworkSrf + 留存两族线（最常用）
r = PWL.network_with_lines(doc, curves_u, curves_v, tolerance=0.01)
# r['brep'] / r['line_ids']

# Sweep2 + 留存 2 条 rail 与全部截面
r = PWL.sweep2_with_lines(doc, rails=[r1, r2], sections=secs, tolerance=0.01)
# ⛔ rail 必须一起留存 —— 别人最容易忘的就是它

# Loft（仅等截面时用）+ 留存全部截面
r = PWL.loft_with_lines(doc, sections, closed=False)

# 交付前自检
print(PWL.audit_curve_retention(doc))   # {'ok': True, 'count': 50, ...}
```

⚠️ **本封装尚未经真机验证**（编写时 Rhino 进程已退出）。它因此：

- `CreateSweep2` / `CreateNetworkSrf` **不硬编码参数个数**，
  而是从 `__doc__` 解析可用重载的 arity 再调用 —— 避免版本差异导致 `No overload`
- 严格校验输入（rails 必须恰好 2 条、sections 非空、cap 必须给公差）
- 失败时抛明确异常，不静默返回空
- `register=False` 时纯内存构造，不碰文档

⚠️ **首次使用请先在内存里跑一遍**（`register=False`），确认无误再落文档。
若某个封装在你的 Rhino 版本上报参数错误，把 `__doc__` 的内容发出来即可定位 ——
这正是加反射层的原因。

### 3.5 实现要点（RhinoCommon）

⚠️ **不要在运行时删曲线。** Rhino 的构面命令会把输入曲线标记为 consumed，
但曲线对象**仍然存在于文档里**（只是隐藏了）。

```python
import Rhino.Geometry as G
import Rhino.DocObjects as D

# 建层（先设 Name 再 Add —— 传字符串会失败）
layer = D.Layer()
layer.Name = 'Lines'
layer_index = doc.Layers.Add(layer)

# 把构面输入曲线放进去
for curve in construction_curves:          # 你的构面输入曲线列表
    attr = D.ObjectAttributes()
    attr.LayerIndex = layer_index
    doc.Objects.AddCurve(curve, attr)

doc.Layers.FindName('Lines').IsVisible = True   # 确认可见
```

⚠️ **先取副本再构面**。让命令去消耗原曲线对象，之后不好管理：

```python
working = [c.DuplicateCurve() for c in design_curves]   # 工作副本
brep = G.Brep.CreateFromLoft(working, ...)                # 命令消耗 working
# design_curves 保持完整，进 Lines 图层
```

### 3.6 ⭐ 交付前的自检

```
□ 每个曲面都能指出它的输入曲线
□ 输入曲线都在 Lines 图层
□ 图层可见（不要留在隐藏状态）
□ 用 Design 面板能直接双击曲线进入编辑
□ ⛔ 没有"只在对话里说过、文件里找不到"的曲线
```

⛔ **做不到"从成品曲面反查到它的输入曲线"**，交付就是不合格的。

## 4. ⭐ 施工顺序（含两条新铁律）

在 [13 施工纪律](13-construction-discipline.md) 的三条铁律之后，补充：

### 铁律 4：⛔ 复杂物体禁止用 Loft 做主体

```
判定：主体是自由曲面（双向曲率变化）→ 必须网格线 + NetworkSrf
      主体是等截面（形状相同、位置递进）→ Loft 可以
```

**理由**：Loft 的段内无约束特性决定了它不适合自由曲面。

### 铁律 5：⭐ 构面输入曲线全部留在文件里

```
判定：每张曲面构造时同步登记它的输入曲线 → 全部进 Lines 图层
理由：曲线是用户唯一的修改入口
```

⚠️ 这两条都**不可事后补救** —— 曲面做成烘死的、或曲线被删了，
只能整块重做。

## 5. ⭐ 快速自检：三个问题

开工前问自己：

```
1. 这个面在 U、V 两个方向各需要几个约束点？
   → 都 >1 → NetworkSrf，不是 Loft

2. 做完之后，用户能改吗？
   → 输入曲线在文件里吗？在 Lines 图层吗？

3. 我能用一句话说清"这张面为什么这么建"吗？
   → 说不出 → 方案本身有问题，不是执行有问题
```

## 6. 来源

第 1.2 节的对比基于 Rhino 8 实测：同一收缩壳体分别用 3 条截面 Loft
与 5×5 网格 NetworkSrf 构造，��察截面周长在高度方向的变化差异。
第 3 节规则来自实际交付场景：曲线丢失后交付物不可编辑。
